# Existing preview migration

Owner: local OurChival vault. Started 2026-09-08 by the archive owner through
Codex. Objective: inspect the existing image assets and replace bulky browsing
media with compact previews without deleting originals or saved evidence.

The initial read-only inventory found 22,038 assets, 21,460 with both preview
sizes, 21,365 with Drive originals, 671 with local originals, and 60 already at
recipe version 2. Original-location counts can overlap.

## Operation

The `compact-previews-v2` record in `previewMigrations` owns the cursor, bounded
pending-job list, counters, errors, and next wake time. Four images are processed
at a time. A ten-second scheduler checks the current batch before advancing.
A minute cron recovers an interrupted scheduler. The service resumes when the
Mac wakes and the local vault is available; this migration does not prevent
sleep or require a Codex conversation to remain open.

The finish condition is a complete asset scan with every pending job settled.
`failed` and `skipped` remain explicit exceptions, not successful conversions.
Four consecutive failures or a job older than thirty minutes pause the run.
The first forty failure identities/reasons are retained in the private state.

The migration only changes derived images. Local-only originals are retained;
uploading and verifying those originals is a separate migration. Existing
AVIF/WebP derivatives are kept when they are already smaller or when another
record still needs that exact object. Recipe 2 therefore means inspected under
the compact policy, not necessarily converted to AVIF. Newly required previews
can add bytes where no preview existed before.

The initial 20-item pilot revealed that saved analysis retained some old
previews. Replacing them added roughly a few megabytes rather than reclaiming
space, so the pilot was paused and the retain-if-smaller-or-referenced guard
was added before resuming. Historical retained evidence is not swept away.
`reclaimedBytes` records deleted object bytes minus newly generated bytes; it
can be negative and is not a promise of filesystem free-space change.

## Controls

Run from the canonical checkout:

```sh
node scripts/compact-preview-migration.mjs inventory
node scripts/compact-preview-migration.mjs status
node scripts/compact-preview-migration.mjs pause
node scripts/compact-preview-migration.mjs start
```

These commands target only `127.0.0.1:3210`, use the local deployment credential
in memory, and print compact counts rather than catalog content or credentials.
Start is idempotent. Resume preserves the existing cursor; it does not silently
retry previously failed items or restart a completed scan. Inspect recorded
failures before arranging a targeted retry.

## Browsing behavior

Here, the user is trying to see saved images quickly without fetching originals.
Cards, quick look, the inspector, review decks, tag examples, and related-image
previews automatically use only stored thumbnails or viewing previews. A visible
gallery or review item without either requests preview generation;
the server bounds demand-driven work and the client backs off when busy.
Original and arbitrary source-image URLs are excluded from automatic fallback
lists. Existing explicit source/Drive links remain available. Sensitive-preview
visibility is respected before requesting a missing preview.

## Verification

Tests exercise cursor resume, duplicate wakes/start, failure pause, preservation
of existing media on failure, compact-source selection, no-growth replacement,
and retained original/artwork/analysis references. Browser visual checks are
limited by the active archive filters and available visible items; do not infer
whole-library visual coverage from the 12-image codec benchmark.

The broader hard disk-cache budget and Drive-backed derivative cache from
`BOUNDED_LOCAL_MEDIA.md` remain separate work. This run is not an original-file
purge, not a historical orphan sweep, and not a backup-chain rewrite.
